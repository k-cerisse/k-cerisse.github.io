# Final Project Rubric – GitHub Pages Portfolio

Total: 100 points
Submission: Public GitHub Pages URL
Due: Final class (replaces a traditional final exam)

## 1. Git & GitHub Workflow and Documentation (15%)

Purpose: Assesses authentic development over time and professional version-control practice.
Excellent (13–15)
Consistent, incremental commits showing clear project evolution
Commit messages are descriptive and meaningful
Repository structure is logical and professional
README.md clearly explains project purpose, tools used, and how to navigate the project
Competent (10–12)
Regular commits with some clustering
Repository structure is mostly clear
README.md present but limited in detail
Basic (7–9)
Minimal commits or vague commit messages
Weak repository organization
README.md incomplete or unclear
Limited (<7)
Few or single-session commits
Repository suggests last-minute assembly
No meaningful documentation


## 2. Website / HTML / Markdown Structure (15%)

Purpose: Evaluates clarity, organization, and effective use of web-based presentation tools.
Excellent (13–15)
Effective and confident use of Markdown/HTML syntax
Clear hierarchy using headings, sections, and navigation
Content is easy to follow and logically structured
Competent (10–12)
Correct syntax with minor structural issues
Layout is readable but not refined
Basic (7–9)
Limited formatting or inconsistent structure
Limited (<7)
Poor layout or difficult-to-follow content

## 3. Computational Tool: Python Program or Excel System (30%)

Purpose: Core technical component assessing applied computation using kinesiology-related data.
Excellent (27–30)
Fully functional Python script, notebook, or Excel system
Correctly processes kinesiology-related data
Inputs or data changes clearly affect outputs (dynamic behavior)
Code, formulas, or logic are clearly documented
Competent (22–26)
Functional analysis with limited flexibility
Documentation present but incomplete


Basic (18–21)
Program runs but logic is shallow or rigid
Minimal explanation of how the computation works
Limited (<18)
Non-functional, static, or largely copied without understanding

## 4. Programmatic Data Visualization (20%)

Purpose: Assesses dynamically generated charts directly linked to computation.
Definition of programmatic/dynamic:
Charts and tables are generated from Python code, a notebook, or Excel formulas and update when
the underlying data changes.
You are _not_ required to run code in the browser or create a live web app.
Excellent (18–20)
Charts are generated programmatically from the analysis
Appropriate chart types are chosen for the data
Visuals update automatically when data changes
Clear, accurate, and professional presentation
Competent (14–17)
Charts are mostly dynamic but limited in number or refinement
Basic (10–13)
Charts rely partly on manual steps or static exports
Limited (<10)
Static screenshots pasted without reproducible computation
Note: Static images of charts without underlying logic will not score highly in this category.


## 5. Additional Technical or Logic-Based Component (10%)

Purpose: Rewards one distinct technical element not already assessed in Sections 3 or 4.
This may include one of the following:
Scratch maze or logic-based program
A secondary Python/Excel feature extending the main analysis
A simple interactive or automated component demonstrating logic or control flow
Excellent (9–10)
Clearly functional and logically sound
Demonstrates independent problem-solving
Competent (7–8)
Functional but simple or limited in scope
Basic (5–6)
Minimal logic or weak integration
Limited (<5)
Decorative or non-functional
Work assessed here must not duplicate computation or charts already graded elsewhere.

## 6. Written Communication & Site Usability (10%)

Purpose: Ensures clarity, professionalism, and coherence across the site.
Excellent (9–10)
Writing is clear, concise, and purposeful
Headings, links, and internal references function correctly
Minimal grammar or spelling issues


Competent (7–8)
Generally clear writing with minor issues
Basic (5–6)
Writing lacks clarity or cohesion
Limited (<5)
Difficult to read or poorly edited

## Overall Expectations

Highest marks are awarded for functional, dynamic work
Static, cut-and-paste content alone cannot earn top grades
Git history and project evolution matter
Each rubric category assesses a distinct contribution
Creativity, integration, and clear thinking are rewarded
This project is intended to be a public-facing portfolio and a living résumé.
